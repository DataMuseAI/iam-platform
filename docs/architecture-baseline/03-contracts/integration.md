# Product and IdP integration contract
- Keycloak version baseline 26.7.3, one realm/environment; discover authorization, token, JWKS and logout endpoint URLs from issuer metadata. No custom `/authorize`/`/token` implementation. Validate feature configuration in staging; do not export admin secrets or realm state into app repo.
- Per product register confidential BFF OAuth client and separate product API audience. Service client credentials for decision endpoint restricted to its own product ID; never grant wildcard product access. No implicit/password grants. PKCE S256, exact redirect URI registration and state; nonce for OIDC. No third-party ID-token as product API bearer.
- SDK contract: `verifyAccessToken(token,{issuer,audience})`, `requireTenantResource(tenantId,resourceTenantId)`, `checkPermission({userToken,tenantId,productId,permission})`; typed errors; safe JWKS caching and key rollover. Caller MUST load product resource by `(tenantId,resourceId)` itself. Admin endpoints use admin audience and explicit privileged authorization.
- Internal decision calls: confidential service credential + end-user access token in request body; redacted by gateway/logging/traces. Service authenticates caller client and verifies user token audience is that client's registered API; determines subject from JWT. Token not reissued by IAM. Never cache full JWT in response/log.
- IdP organizations may help invitation/federation, but IAM DB membership is canonical. Reconciliation job compares stable IdP org IDs against mapping, alerts on mismatch. No automatic account linking by email, no authorization based only on email domain.
- Events `membership.suspended`, `role.changed`, `tenant.suspended`: event_id, version, timestamp, tenant_id, product_id optional, minimal subject ID; no PII by default. Signed webhook on later phase; at-least-once, deduplicate by event_id and sequence by aggregate version.

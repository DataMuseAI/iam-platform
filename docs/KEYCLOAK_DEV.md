# Keycloak development setup (G0 manual checklist)
This is a **manual configuration checklist** for local testing, not a claim that Keycloak was configured. Start compose and sign in to Keycloak admin at `http://localhost:8080` using development bootstrap credentials, then change passwords for any shared environment.

1. Create realm `saas-dev`; enable user registration only if intended and email verification after configuring a development mail server. No security controls should be disabled to make tests pass.
2. Create an API audience client `iam-api` and resource API audience `demo-api` (names as audience strings). Create an interactive confidential test BFF client using Authorization Code and S256 PKCE; register exact callback URL. Configure audience mapper/scope so only appropriate API access tokens include `iam-api` or `demo-api`. ID tokens must not be accepted by APIs.
3. Create a confidential service-account-only client `demo-service`. Enable Client Credentials, **disable browser authorization/password grants** on this client; configure its access-token audience `iam-api`. Copy the service account subject (`sub`) from a service access token to `DEMO_SERVICE_SUBJECT`; client ID must match `DEMO_SERVICE_CLIENT_ID`. Rotate secrets and keep them out of git.
4. Create one platform operator user and separate pilot end user via Keycloak UI. Obtain operator issuer and immutable subject from ID token/admin view. Grant `iam-api` audience to operator's API access token, then run `seed:admin` with verified issuer/sub. This bootstrap is intentionally outside public API.
5. Confirm by decoding tokens locally: issuer exactly `OIDC_ISSUER`, access token aud for API, service `azp` or `client_id` equals `demo-service`, service subject exactly configured; signature is checked in server code. Execute negative-audience test before trusting setup.

For interactive testing, use an OIDC capable tool/client using Authorization Code+PKCE. Never use Resource Owner Password Credentials grant just for convenience. Keycloak Organizations and external IdP federation are not required for pilot; test in separate G3 spike if sold. Production requires TLS, private admin plane, external secrets, hardened realm settings and non-default passwords.

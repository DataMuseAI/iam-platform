# Status and work required before external users
The implementation is a vertical slice, **not** a production-grade shipped product. G0: run npm typecheck/test, apply SQL against PostgreSQL 17, verify Keycloak 26.7.3 realm/audience config in staging, pin digests and lockfile. G1: add real BFF Auth Code+PKCE web login and admin UI, invites/email, admin membership lifecycle, two-product isolation E2E and secure bootstrap/idempotency. G2: immutable audit sink/outbox worker and retries, database runtime roles, case-by-case GDPR workflows, emergency access, security review, HA deployment, backup and DR evidence. G3: SAML/OIDC federation, SCIM, independent pen test where customers require them.

Known code limitations: pilot tenant creation allows only platform-admin self-ownership; no member invitation/acceptance or safe owner transfer is implemented. no RLS, no rate limiting, no service key revocation pipeline, no MFA-enforced privileged endpoint beyond IdP admin configuration, no service token audience mapper automation, no programmatic migrations tested, no app-level mTLS, no CSRF-safe BFF, no permission catalog management UI, no full error taxonomy, no request idempotency, no invitation handling, no real multi-product fixture. `iam` decisions read DB on every request and therefore fail closed but not scalable without a designed cache/invalidator. Audit events are DB records only, not immutable evidence. No test here substitutes for deployment verification.

Safety: NEVER use `start-dev`, compose passwords or localhost issuer in production; externalize secrets, TLS and configure CORS/headers deliberately; require privacy/legal review of consent, DPA, processing and retention. Do not assert GDPR/ASVS compliance without control-by-control evidence.
